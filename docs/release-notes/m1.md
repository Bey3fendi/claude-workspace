# M1: failures visible (plan v1.0, items 0.1 and 1.1 to 1.5)

- Freeze until 1.0 (rule R5) is stated in the README. The old plan moved to `docs/history/PLAN.md`; the 1.0 plan is `docs/PLAN-v1.0.md`, with the decisions recorded in its section 11 (default profile `standard`; attribution removal only in `full`; reduced release gate: 3 runs per scenario per condition, advice at least 2 of 3, Sonnet as reference plus a short Opus pass; skill pack decided after 1.1).
- One error policy for all 21 workspace-core hooks: each fails open and records a `hook.error` row (`hook`, `kind`: throw or timeout, a short redacted `message`). A failure before the hook's `next()` runs the rest of the chain once; a failure after it keeps that result. Nothing runs twice. The 5 hooks that had no `.catch` (`session.start`, `session.end`, `turn.start`, `turn.step`, `skill.prompt`) now have one.
- Parts a hook guarded itself and dropped silently (stop check, memory end-of-request, Ponytail close, edit check, pre-edit hold, Bash-edit snapshots, Explain check, `/ci` and `/explain` prompts, event-log setup) now record a `hook.error` row with `part` set.
- The engine asks one `.catch` per event for the module, so the three `tool.call` hooks record `hook: "tool.call"` with `part: "tool <name>"`.
- Footer: a request with a hook error gets a second line, `workspace-core: 1 hook error (prompt.submit)`. It shows alone when there is nothing else to report.
- `claude-workspace usage` lists the session's hook errors (hook, part, kind, message); its JSON has `hookErrors`.
- `doctor` has a new `hook-errors` check: a warning when the project's most recent recorded session had any, ok when it had none, absent when no session is recorded.
- Check commands made visible: the footer shows `workspace-core: stop check: npm test · edit check: … (from .claude/workspace.json, run with sh -c)` once per session (and again if the commands change). It is shown only, never written to the event log. `doctor`'s `check-hooks` line now says where the commands come from and when they run.
- CI: unit tests on `ubuntu-latest` and `macos-latest`. A new `engine` job (both systems) installs Claude Code at the newest version in `workspace.lock.json` `claudeCode.tested` (2.1.317 today, through npm), then runs `claude plugin validate .`, `claude plugin validate --strict plugins/workspace-core` and `claude plugin test plugins/workspace-core`. Checked locally on 2.1.317 and 2.1.325: 120 engine tests pass on both.
- New engine tests (`plugins/workspace-core/tests/hook-errors.test.ts`): a fault before and after `next()` for each hook the test kit can raise (20 of 21: `state.set` is raised only by the plugin that owns the value, the router, so the kit cannot raise it; it has the same `.catch`); no `hook.error` row without a fault; the footer lines; and the review's two fault tests (Bash and Stop, a fault after `next()`) kept as regression tests.
- Golden replay fixtures regenerated: they gain only empty `hookErrors` arrays.

New env switch (test seam only, not for users): `CW_TEST_FAULT=<hook>:<before|after>[,…]` (or `*:<at>`) makes that hook throw before or after its `next()`. Read once per process.
