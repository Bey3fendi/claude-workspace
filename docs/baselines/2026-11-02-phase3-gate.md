## Workflow outcomes: improved, with one gap

| Check | Gate (with, n=2) | Run 1 nocontract (n=1) |
|---|---|---|
| feature: design step before any src edit | **2/2** | 0/1 |
| tdd: test → failing run → src | **2/2** | 0/1 |
| coverage: tests run after writing, src untouched | 2/2 | 1/1 |
| debug: target test passes, Karpathy-minimal diff | 2/2 | 1/1 |
| **debug: root cause stated before the first edit** | **0/2** | 0/1 |
| Runs passing all hard checks | **6/8 · 75% [41%–93%]** | 1/4 · 25% [5%–70%] |

**The debug gap is genuine, not a grader artefact.** In both runs the model:
- invoked `systematic-debugging`;
- read the code and ran the tests;
- edited at once;
- stated the cause only afterwards.

The earlier single recheck passed, so the advisory wording works sometimes (1/3 overall), but not reliably.

**This is not significant at this sample size.** The run-level intervals overlap; the per-check results point the same way as the activation result.

## Verdict

- **Activation gate: met** (20/20 [84–100] vs 0/51 [0–7]).
- **Listing:** trimmed on A/B evidence with no activation loss (`2026-11-02-phase3-listing-ab.md`).
- **Outcomes: improved for feature and TDD workflows.**
- **"Root cause before fix" is not achieved by advice alone.** It is a Phase 4 enforcement candidate: a `tool.call` gate that holds the first `src/` edit in a debug-class request until the model has stated a root cause.
